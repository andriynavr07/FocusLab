# Історії користувача та критерії приймання

**Проєкт:** FocusLab (Windows Desktop, .NET 8 / WPF / EF Core / ADO.NET / SQLite)

---

## 1. Модуль задач (Task Management)

### 1.1. Створення та налаштування задачі

Як **студент або розробник**,
я хочу **створювати нові задачі із зазначенням назви, опису, дедлайну, пріоритету та проєкту**,
щоб **зафіксувати необхідну роботу та структурувати свій розклад**.

**Критерії приймання (Acceptance Criteria):**

- [ ] Поле «Назва» є обов'язковим для заповнення (довжина від 1 до 255 символів). Без назви кнопка збереження неактивна або видає валідаційне повідомлення.
- [ ] Користувач може вибрати один із 4 пріоритетів: Низький, Середній, Високий, Критичний (за замовчуванням — Середній).
- [ ] Користувач може призначити дедлайн (дата і час).
- [ ] Задача може бути прив'язана до існуючого проєкту або залишена в загальному списку («Без проєкту»).
- [ ] Створена задача автоматично потрапляє у першу колонку Канбан-дошки («До виконання»).
- [ ] Дані успішно зберігаються в локальну БД SQLite через EF Core.

### 1.2. Переміщення задач по Канбан-дошці (Drag & Drop)

Як **користувач**,
я хочу **візуально перетягувати картки задач між колонками статусів**,
щоб **наочно бачити та швидко змінювати поточний стан виконання роботи**.

**Критерії приймання (Acceptance Criteria):**

**Given (Дано):** На дошці є колонки «До виконання», «У процесі», «На перевірці», «Виконано».

**When (Коли):** Користувач затискає картку задачі лівою кнопкою миші та перетягує її в іншу колонку.

**Then (Тоді):**

- Статус задачі в моделі змінюється на відповідний новій колонці.
- Зміна статусу зберігається в БД асинхронно без блокування UI.
- Якщо задачу перенесено у статус «Виконано», вона візуально позначається як завершена (наприклад, перекреслення або чекбокс), а час завершення фіксується.

### 1.3. Фільтрація та підсвічування задач

Як **користувач із великою кількістю завдань**,
я хочу **фільтрувати дошку за тегами та бачити кольорове попередження про прострочені дедлайни**,
щоб **сфокусуватися на найбільш термінових або специфічних завданнях**.

**Критерії приймання (Acceptance Criteria):**

- [ ] Панель фільтрів дозволяє вибрати один або кілька тегів (фільтрація застосовується миттєво без перезавантаження вікна).
- [ ] Якщо дедлайн задачі минув і її статус не «Виконано», дата або рамка картки підсвічується червоним кольором.
- [ ] Підтримується пошуковий рядок: картки фільтруються за входженням підрядка в назву задачі.

## 2. Модуль швидкого запуску ресурсів (Quick Launcher)

### 2.1. Прикріплення локальних файлів, папок та URL до задачі

Як **студент або програміст**,
я хочу **додавати посилання на потрібні файли, папки проєкту або веб-сторінки безпосередньо в картку задачі**,
щоб **не шукати їх щоразу вручну у файловому провіднику чи закладках браузера**.

**Критерії приймання (Acceptance Criteria):**

- [ ] Можливість додати ресурс трьох типів:
  - Локальний файл (через діалогове вікно вибору файлу OpenFileDialog або перетягуванням Drag & Drop).
  - Локальна папка (через діалогове вікно вибору папки).
  - URL (текстове поле з валідацією валідності інтернет-посилання http:// або https://).
- [ ] До однієї задачі можна прикріпити необмежену кількість ресурсів.
- [ ] Кожен прикріплений ресурс має відповідну візуальну іконку (файл, папка, браузер) та відображає назву або скорочений шлях.

### 2.2. Миттєве відкриття прикріпленого ресурсу

Як **користувач**,
я хочу **відкривати прикріплений ресурс в один клік із картки задачі**,
щоб **негайно перейти до виконання завдання**.

**Критерії приймання (Acceptance Criteria):**

**Given:** У картці задачі є прикріплений файл/папка/посилання.

**When:** Користувач натискає на прикріплений ресурс.

**Then:**

- Якщо це файл/папка, система перевіряє їхнє існування (`File.Exists` / `Directory.Exists`):
  - якщо існує: викликається системний процес (`Process.Start`) для відкриття в асоційованій програмі Windows або Explorer;
  - якщо не існує (видалено або переміщено): показується зрозуміле спливаюче сповіщення про помилку (наприклад: «Файл за шляхом ... не знайдено»), без аварійного закриття програми (crash).
- Якщо це URL: адреса відкривається у браузері користувача за замовчуванням.

## 3. Модуль фокусу (Pomodoro Timer)

### 3.1. Запуск фокус-сесії для конкретної задачі

Як **студент під час підготовки до іспиту або фрілансер**,
я хочу **запускати Pomodoro-таймер безпосередньо для обраної задачі**,
щоб **концентровано працювати заданими інтервалами та точно фіксувати витрачений час**.

**Критерії приймання (Acceptance Criteria):**

- [ ] Користувач може розпочати фокус-сесію безпосередньо з контекстного меню або кнопки на картці задачі.
- [ ] Відображається таймер зворотного відліку (за замовчуванням 25 хвилин) з круговим або лінійним індикатором прогресу.
- [ ] Доступні кнопки керування: Старт, Пауза, Скинути/Зупинити.
- [ ] Інтерфейс у фокус-режимі ховає зайві відволікаючі панелі.
- [ ] При згортанні застосунку таймер продовжує коректно працювати у фоновому потоці.

### 3.2. Завершення сесії та чергування періодів відпочинку

Як **користувач**,
я хочу **отримувати сповіщення про закінчення робочої сесії та автоматичний перехід до фази відпочинку**,
щоб **дотримуватися балансу роботи і відновлення сил**.

**Критерії приймання (Acceptance Criteria):**

- [ ] По закінченню таймера (00:00) користувач отримує звукове сповіщення та нативне Windows-повідомлення.
- [ ] Завершена сесія автоматично записується в локальну базу даних SQLite із фіксацією: `TaskId`, `StartDateTime`, `DurationMinutes`, `IsCompleted = true`.
- [ ] Таймер автоматично перемикається на коротку перерву (5 хв).
- [ ] Після кожних 4-х успішних фокус-сесій система пропонує довгу перерву (15–20 хв).

## 4. Модуль аналітики та звітності (Analytics & SQL Reporting)

### 4.1. Перегляд статистики продуктивності

Як **розробник/фрілансер**,
я хочу **бачити аналітичні графіки розподілу робочого часу по днях і проєктах**,
щоб **аналізувати свою ефективність та знати, скільки часу витрачено на кожного клієнта**.

**Критерії приймання (Acceptance Criteria):**

- [ ] Інтерфейс містить окрему вкладку «Аналітика» з вибором періоду: Сьогодні, Поточний тиждень, Поточний місяць.
- [ ] Відображаються зведені показники:
  - Загальний час у фокусі (години / хвилини).
  - Кількість завершених Pomodoro-сесій.
  - Кількість закритих задач.
- [ ] Відображається діаграма розподілу часу за проєктами/тегами.
- [ ] Агрегація даних для аналітики формується через оптимізовані ADO.NET SQL-запити (`GROUP BY`, `SUM`) для уникнення накладних витрат ORM при великій кількості записів.
- [ ] UI не зависає під час формування звіту (запит виконується асинхронно через `ExecuteReaderAsync`).

## 5. Системні та нефункціональні вимоги (System & Offline-First)

### 5.1. Автономний старт та робота без інтернету

Як **користувач**,
я хочу **відкривати та використовувати програму без підключення до інтернету**,
щоб **мати доступ до своїх задач у будь-яких умовах**.

**Критерії приймання (Acceptance Criteria):**

- [ ] При першому запуску програми база даних SQLite створюється автоматично на диску користувача (`%AppData%` або поруч із бінарником), застосовуються всі міграції EF Core.
- [ ] Застосунок запускається та зберігає працездатність на 100% функціоналу в режимі «У літаку» (без доступу до мережі).
- [ ] Час холодного запуску застосунку на середньому ПК не перевищує 2–3 секунд.
